## CS-01 · FIX · \[Main → Mood Trend → Edit focus areas\] · "+Add new" chowa się pod klawiaturą; nazwa objawu z dużej litery

- **Type:** FIX  
- **Location:** Main → Mood Trend module → pencil icon → bottom sheet "Edit focus areas" → the "+Add new" row at the bottom of the sheet → its inline text field. `verified: mindsync_app/lib/screens/stats_tab/widgets/symptom_management_sheet.dart` — opener `unified_symptom_module.dart:139`; sheet column `:66`; list cap `:105-108` (`ConstrainedBox(maxHeight: MediaQuery.of(context).size.height * 0.62)` \+ `SingleChildScrollView`); bottom inset `:47-48, 64` (`math.max(viewInsets.bottom, padding.bottom)`); `_AddNewRow` `:191-195` (outside the scroll view); the `TextField` `:321-340`; save path `:254-266` → `verified: lib/screens/stats_tab/cubit/symptom_tracking_cubit.dart:225-232` (`addSymptom`) → `verified: lib/api/api_managers/symptom_manager.dart:28-31` (`POST /api/v1/symptoms/`, body `{name, is_custom}`). ARB: `stats_addNew` "Add new", `stats_addNewHint` "e.g. Sleep, Anxiety, Motivation" (`app_en.arb:845-846`).  
- **Now (wrong):** The sheet is one non-scrolling `Column`: handle → title → the Active/Archived list capped at 62 % of the *whole screen height* → the "+Add new" row. The bottom padding does follow the keyboard, but the list cap does not shrink when the keyboard opens. With enough active items to hit the cap, the column overflows the sheet and the field with its confirm/cancel buttons sits behind the keyboard, and nothing can scroll it into view (the row is outside the `SingleChildScrollView`; there is no `ensureVisible`). With 3–4 items the field is fine, which is why it looks intermittent. Separately, the `TextField` sets no `textCapitalization`, the sheet only `trim()`s the name, the cubit and API pass it through, and the display path (`lib/utils/symptom_presets.dart:25-31`) returns custom names verbatim: typing "sleep" stores and shows "sleep", while the hint promises "Sleep, Anxiety, Motivation".  
- **Expected:** (1) The field and its confirm/cancel are fully visible above the keyboard whenever the field has focus, regardless of how many active items exist. (2) The keyboard opens with sentence capitalization, and the saved name always starts with an uppercase letter no matter what was typed ("sleep" → "Sleep"). (3) Decision 18.08: existing custom names saved in lowercase also render with a capital first letter (display-side normalization), so older entries stop looking different from new ones; the stored value is not rewritten.  
- **Logic:** tap "+Add new" → field opens and takes focus → keyboard rises → the sheet re-lays out so the field sits directly above the keyboard (the list gives up height or the whole sheet scrolls to the field; implementer's call) → type → confirm → the name, first letter uppercased, lands in Active and is tracked at once (CS-04 of MSV3.4 behaviour) → keyboard closes → the sheet returns to its normal layout.  
- **Not this:** do not move the field to the top of the sheet or into the scrolling list to dodge the problem; it stays where MSV3.4 CS-04 put it (below Active/Archived) and the layout is fixed instead.  
- **Do NOT touch:** Active/Archived rows and their archive/restore/delete; the reorder mechanism (CS-02); the backend symptom endpoints beyond normalizing the first letter.  
- **Done when:** On a phone with at least 8 active focus areas, tapping "+Add new" shows the field and both buttons entirely above the keyboard, iOS and Android; the same with 1 item; the keyboard shows capital-letter mode; typing "sleep" produces "Sleep" in Active and in Mood Trend; a pre-existing lowercase custom name renders capitalized in the sheet and in Mood Trend; nothing else in the sheet changed.  
- **Risk:** Low. One file plus a one-line normalization.
