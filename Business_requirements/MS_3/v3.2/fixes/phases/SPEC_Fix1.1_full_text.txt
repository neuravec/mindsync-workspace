CS-09 · CHANGE · [Main] · &quot;Next therapy session&quot; — formats + state-dependent buttons
Type: CHANGE
Location: Main → module 1 → Next therapy session (countdown + action area).
What it is: Countdown module with action-reminder elements guiding the user through the session cycle.
Action: Keep the countdown with the existing action-reminder elements; change format and add state-dependent buttons. Countdown formats:
&gt;24 h to session: day + time, e.g. &quot;jutro o 12:45&quot;, &quot;czwartek o 10:00&quot;. No minute countdown. Sessions further out than the weekday horizon: keep the current display as-is (Darek, 2026-07-05: &quot;Don't change anything. It's already good as it is now&quot;) — no new format work beyond these two rules.
&lt;24 h: &quot;dzisiaj o [godzina sesji], za x godz y minut&quot;. State chain (confirmed): set session → prep CTA → session happens → debrief CTA → between-sessions encouragement → next session (loops). States &amp; buttons:
No therapy set: button opening a hub-and-spoke flow to set therapy date, time, cadence (kiedy się odbywa) and with whom — writes the SAME fields as settings' session data.
No prep done before upcoming session (zero &quot;przygotowanie do terapii&quot;): button → przygotowanie do terapii.
Session already happened — begins at the session's start time (per decision): button → debrief po terapii.
After debrief (between-sessions period): encouragement → between sessions. Embedded bug (fold — per decision): currently, after completing the debrief the module does NOT switch to between-sessions, and the next session stopped displaying even with weekly cadence set. Both are state-machine defects this rebuild must fix.
Logic:
Set-therapy button → tap → hub-and-spoke opens → save → module shows countdown; settings reflect the same data
Prep button → tap → przygotowanie do terapii flow
Debrief button → tap → debrief po terapii flow; on debrief completion → module switches to between-sessions state
Between-sessions encouragement → tap → between sessions feature
Cadence rollover: once a session's debrief is done (or the between-sessions state begins), the next session per cadence becomes the new countdown target
Outcome: The module always tells the user the one next thing to do, and never strands them after a debrief.
Value: The state chain is the app's core loop; a stuck state kills the cycle.
Do NOT touch: Existing reminder elements (&quot;tak jak jest obecnie&quot;); settings' session data model; the current far-out-date display.
Done when: Both countdown formats render per the examples; each state shows its button/encouragement; hub-and-spoke saves the same fields as settings; completing a debrief flips the module to between-sessions; with weekly cadence set, the next session appears automatically; state transitions correct across the day boundary and at session start time.
Risk: Medium — state machine with time edge cases (e.g. session starting right now).
