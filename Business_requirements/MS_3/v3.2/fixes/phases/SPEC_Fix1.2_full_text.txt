Summary
Total items: 25 (DELETE: 0 · FIX: 7 · CHANGE: 18)
Areas touched: bottom nav · output-card triage (cross-module) · NEW module „Tematy i pytania&quot; · Agenda następnej sesji · Do zrobienia · Wątki · Realizations · Goals · Therapy Relationship · check-in reminder card
Intent: turn Workspace into a mostly self-feeding hub. AI-detected items on output cards become tappable chips routed to dedicated modules (Tematy i pytania, Wątki, Do zrobienia); Agenda becomes a user-curated session list fed from those modules — nothing enters it without a user tap. On top: one unified add-entry sheet (with voice input), unified archives with restore, expand/collapse for long lists, and a set of dead-button and formatting fixes.

Format note (per author): items carry a short User flow (context for the coding agent) and AI flow (context for the AI layer). Both fields are omitted where the item touches neither.
Global guardrails (read before touching anything)
Do NOT touch: the generated content of output cards (after-therapy / prep / between-sessions note / recording) — triage only APPENDS a chip section at the bottom (CS-03).
Do NOT touch: check-in scoring and color-mapping logic — it already works; CS-24 only surfaces stored values.
Do NOT touch: Agenda's existing checkbox close behavior — already built correctly, leave as is (author confirmed).
Do NOT touch: Timeline history and card ordering.
Red „Usuń&quot; in every 3-dot menu = confirmation dialog → permanent delete. Never lands in an archive (author decision).
Every new user-facing string ships PL + ENG (both given per item).
After each item: run the app, confirm no dead references / broken navigation; builds pass Android + iOS.

Shared patterns (single source of truth — items reference these)
P1 · Add-entry bottom sheet
Used by CS-05, CS-09, CS-13, CS-18, CS-22. Trigger: one wide ghost button at the bottom of the module frame („+ Dodaj …&quot; — label per item).

UI anatomy (top to bottom):

Top: sheet title (= button label without „+&quot;) + X (top-right)
Middle: text field
Bottom row: left — button „Nagraj&quot;; right — primary button „Zapisz&quot;

Logic:

Ghost button → tap → card slides up from the bottom.
X → tap → closes sheet sliding down, nothing saved → back to module view.
„Nagraj&quot; → tap → recording UI appears; on stop → speech-to-text result lands in the text field of the previous view; user can read and correct it.
„Zapisz&quot; → tap → saves entry → sheet closes → entry appears at the top of the module's list.

AI flow: „Nagraj&quot; reuses the existing speech-to-text pipeline; on STT failure show the existing recording-error handling, text field left unchanged.
P2 · Archive
Used by CS-05, CS-07, CS-11, CS-15, CS-21.

UI anatomy:

Module header, top-right: small archive icon. Two states: default; notification — small green circle badge with a number = count of items closed since the archive was last opened. The number accumulates; after the user enters and exits the archive, the icon returns to default.
Archive opens as hub-and-spoke (full view over the module).
Top: title (per item) + X — closes and returns to the previous view.
List of closed items, newest first, each showing its close date.
Each row: action „Przywróć&quot; / &quot;Restore&quot;.

Logic:

Closing an item in the module (checkbox) → item leaves the module list → appears in its archive with today's date → badge +1.
Archive icon → tap → archive opens; after exit the badge resets to default.
„Przywróć&quot; → tap → item returns to the module's active list (top) → disappears from archive.
An item can also be restored from its source output card (chip states, CS-03).
P3 · Expand/collapse list
Used by CS-05, CS-16, CS-25. Default visible: 5 items, chronological by date added — newest at top, oldest lowest.

Controls at the bottom of the list:

„Pokaż więcej ⌄&quot; / &quot;Show more ∨&quot; → loads the next batch of 10; repeat until the list is exhausted.
„Pokaż mniej ∧&quot; / &quot;Show less ∧&quot; → collapses one batch (−10). Visible only when more than the default is shown.
„Zwiń wszystko ∧&quot; / &quot;Collapse all ∧&quot; → collapses back to the default 5.
When fully expanded, the last records at the bottom show „Wszystkie widoczne&quot; / &quot;All visible&quot;, with „Zwiń wszystko ∧&quot; below it.

CS-03 · CHANGE · Output cards · triage chips feeding Workspace
Type: CHANGE
Location: Every generated output card: after-therapy card, prep card, between-sessions note, recording card → bottom section with AI-detected elements. Reached: Timeline → open any of these cards → scroll to bottom.
What it is: cards already end with elements the AI has picked out, but today they propagate nowhere — Workspace features receive no automatic content. This is the core complaint of the batch.
User flow: user finishes reading a card → sees chips at the bottom grouped by type → taps the ones worth keeping → each lands in the right Workspace module instantly. Workspace fills without manual typing.
AI flow: uses the existing AI extraction — no new generation. Each candidate must carry a type label (Temat / Pytanie / Wątek / Action point) and a source ref (card id + card type). If extraction returns nothing, the chip section is hidden.
UI anatomy (bottom of card):
Chips grouped by type, in this order: Tematy · Pytania · Wątki · Action pointy (group header shown only when the group is non-empty)
Each chip = candidate text, unselected by default — AI never pre-selects any chip
Logic:
Chip (unselected) → tap → selected + instantly sent to its target module: Temat/Pytanie → „Tematy i pytania&quot; (CS-05); Wątek → Wątki; Action point → Do zrobienia.
Chip (selected) → tap → deselected + withdrawn from the target module.
Chip whose item was closed in its module → shows a closed state on the card; tap → restores it to the module's active list (P2).
Unselected chips never disappear: they stay on the Timeline card and can be sent to Workspace at any later time.
Outcome: the choices the user makes on existing cards feed Workspace; nothing is lost, nothing is auto-selected.
Value (author): „Workspace prawie nie wymaga ręcznego wpisywania.&quot;
Do NOT touch: card body content and its generation above the chip section.
Blocked by: CS-05 (target module must exist).
Done when: on all four card types, tapping a chip of each type creates the item in the correct module instantly; second tap withdraws it; unselected chips persist on the card; items closed in a module are restorable from the card.
