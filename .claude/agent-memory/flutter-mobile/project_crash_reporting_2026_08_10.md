Wired automatic unhandled-exception reporting via PostHog on 2026-08-10 (dev commit dc5b340, HEAD 00f8739 -> dc5b340). Previously `$exception` never fired -- only the manual `AnalyticsEvents.logError` -> `client_error` path existed (17 events/14d, confirmed implausibly low vs real crash volume).

**Why:** growth/on-call had zero visibility into unhandled crashes. Constraint: no new vendor (no Sentry/Crashlytics -- Crashlytics needs console enablement = operator task, out of scope).

**Key discovery -- check this on any future PostHog work:** `posthog_flutter` (pinned `^5.0.0`, resolved 5.23.2 in pubspec.lock) ships **built-in error-tracking autocapture** at `PostHogConfig.errorTrackingConfig` -- no manual `FlutterError.onError`/`PlatformDispatcher.onError`/isolate-listener wiring needed. Three independent toggles: `captureFlutterErrors`, `capturePlatformDispatcherErrors` (covers unhandled async/zone errors -- Flutter's zone-independent recommended replacement for `runZonedGuarded`), `captureIsolateErrors`. All three produce the canonical `$exception_list` schema (type/value/mechanism.handled/stacktrace.frames) that PostHog's Error Tracking UI groups on -- more standard than ad-hoc `$exception_type`/`$exception_message` flat properties. There's also `captureNativeExceptions` (Android Java/Kotlin crashes + iOS Mach/POSIX/NSException) -- NOT enabled, needs ProGuard/R8 mapping upload + Xcode dSYM build phase (integration-devops territory), flagged as a follow-up option, not done.

**Sanitization mechanism:** `PostHogConfig.beforeSend` (`List<BeforeSendCallback>`, `FutureOr<PostHogEvent?> Function(PostHogEvent)`) intercepts EVERY event before send, including autocaptured `$exception` events (confirmed via source: `posthog_flutter_io.dart` applies `_beforeSendCallbacks` inside the same `captureException()` impl that both the autocapture integration and manual `Posthog().captureException()` call through). Return `null` to drop, or a modified `PostHogEvent` to continue. **Caveat:** only user-provided properties are visible in `beforeSend` -- system properties (`$app_version`, `$device_type`, `$session_id`, likely `$is_emulator`) are added natively AFTER this hook runs, so they can't be read or need-not be manually added here.

**Sanitizer policy implemented** (mental-health app -- exception messages can embed user-typed content, e.g. `FormatException` echoing parsed text): redact `$exception_list[0].value` to `<redacted>` UNLESS `type` is in a small allowlist (`DioException`, `PlatformException`, `StateError`, `RangeError`, `TypeError`, `UnimplementedError`, `UnsupportedError`, `ConcurrentModificationError`, `NoSuchMethodError`) -- and even then, per-type regex extraction pulls only the safe substring (Dio: `DioExceptionType` + HTTP status code, never body; PlatformException: `.code` only, never `.message`/`.details`). `ArgumentError` and `FormatException` deliberately NOT allowlisted (can carry user values/text). Truncated to 200 chars.

**New module:** `lib/core/analytics/error_reporting/` -- `exception_message_sanitizer.dart` (pure static sanitizer), `exception_rate_limiter.dart` (caps 20 `$exception`/process-lifetime, referencing the `reflect_limit_hit`/1870-events precedent as why this exists from day one), `exception_dedupe_guard.dart` (signature = type + top stack frame, 1s window, collapses the same error double-reported by >1 hook), `posthog_exception_before_send.dart` (`PostHogExceptionBeforeSend` composes all three + a debug-build drop-and-print gate). Wired in `posthog_service.dart` `init()`: `config.beforeSend = [_exceptionBeforeSend.call]`, `config.errorTrackingConfig..captureFlutterErrors=true..capturePlatformDispatcherErrors=true..captureIsolateErrors=true..inAppIncludes.add('package:mindsync_app')`. Kill switch reused: gated entirely behind the existing `POSTHOG_API_KEY` dart-define presence check -- no new flag.

**Documented gap (not fixed):** hooks only install once `PostHogService.init()` completes in `main.dart` (after `Firebase.initializeApp()` + `setupAppLocator()`, before `runApp()`). Exceptions during `WidgetsFlutterBinding.ensureInitialized()`, date-formatting init, orientation lock, `WebRTC.initialize()`, Firebase init, or DI setup are NOT captured (PostHog isn't up yet to send to anyway). Left as-is -- wrapping all of `main()`'s bootstrap risked its own bugs for a low-probability window.

**Test gotcha confirmed:** `runZonedGuarded(() async {...})` with a body that throws BEFORE its first `await` does NOT route to `onError` -- the exception is captured into the `Future` the async closure returns instead (classic Dart async semantics), so `await runZonedGuarded(...)` just rethrows synchronously past the zone entirely. Use a **synchronous** zone body (`runZonedGuarded(() { throw ...; }, onError)`) to actually exercise `onError`, and use a `Completer` if `onError` itself needs to do async work you want the test to await.
