## Deep-link redirect pattern (GoRoute-level `redirect:`)
When a feature's UI location moves but a BACKEND push-notification deep link can't change (old app builds keep sending it for weeks — see CLAUDE.md's H10-style caution), redirect at the ROUTING layer instead of editing the old screen:
```dart
static String? settingsRedirectTarget(Map<String, String> queryParameters) {
  if (parseSettingsSectionParam(queryParameters) == 'therapy_schedule') return myTherapyRoute;
  return null;
}
// on the GoRoute:
redirect: (context, state) => MsRoutes.settingsRedirectTarget(state.uri.queryParameters),
```
- Extracted as a pure function (same convention as the existing `parseSettingsSectionParam`/`parseTabDeepLinkParams`) — unit-testable without pumping GoRouter.
- To prove the REAL production router's `redirect:` callback (not a parallel test copy) actually does this: grab the live GoRoute from `MsRoutes.router.configuration.routes.whereType<GoRoute>()`, build a synthetic `GoRouterState(MsRoutes.router.configuration, uri: Uri.parse(path), ...)`, and `await route.redirect!(context, state)` — same technique `ms_routes_b17_screen_name_test.dart` uses for `pageBuilder`. `context` isn't read by the redirect body, so any mounted widget's context works (`pumpWidget(MaterialApp(home: SizedBox()))` then `tester.element(find.byType(SizedBox))`).
- This left the OLD screen (`SettingsScreen`/`settings_body.dart`) completely untouched — the anchor/scroll logic for `initialSection == 'therapy_schedule'` still exists there for any other in-app path to `/settings` with that query, it's just no longer reached via the redirected deep link.

## Widget-test gotchas hit this session
- **Off-screen tap in a `SingleChildScrollView`**: a fixed 800x600 test viewport plus a content-heavy screen (header + schedule + cadence + duration + modality row) puts later rows below y=600. `tester.tap(find.text(...))` throws "derived an Offset that would not hit test" if the target isn't scrolled into view — fix with `await tester.ensureVisible(finder); await tester.pumpAndSettle();` before tapping (safe there since state is `.loaded`, no indeterminate spinner). `find.text(...)` existence checks (no tap) work fine regardless of scroll offset since `SingleChildScrollView` builds its whole child eagerly (unlike `ListView.builder`).
- **`pumpAndSettle()` timeout on a `.loading()` fixture**: any test that mocks a cubit into a `Loading` state (indeterminate `CircularProgressIndicator`) must use bounded `tester.pump()` + `tester.pump(Duration(...))` for the initial navigation, matching `settings_screen_test.dart`'s established pattern — only call `pumpAndSettle()` in test bodies where the mocked state is guaranteed finite.
- After a go_router `context.push` + pop round-trip, the PREVIOUS route's widget can still be found in the tree (Navigator keeps it mounted, just offstage) — don't assert `findsNothing` on the underlying page's content right after a push; only assert on what's now on top. Assert `findsNothing` on the PUSHED screen only after actually popping back.
- Mocking two independent GetIt-singleton cubits that a screen reads via `sl<X>()` in `initState` (not `context.read`) needs both registered as `sl.registerSingleton<X>(mock)` before pump, each with `.state`/`.stream`/`.init()` stubbed — same pattern as `settings_screen_test.dart`, just doubled up when a new screen (like the hub) owns two cubits.

## l10n conventions confirmed (useful for future batches)
- ARB files are NOT alphabetized — new keys get appended at the end of file, before the closing `}`, grouped as a mini-batch with a blank line separator.
- Diacritic/special-character convention differs by locale: **PL, NB, SV keep full native diacritics** (ą/ę/ł, å/æ/ø, ä/ö — e.g. `"Prøv igjen"`, `"Försök igen"`); **DE, ES, FR strip them** (transliterated ASCII: `"Ausgewaehlte"` not `"Ausgewählte"`, `"seance"` not `"séance"`, `"Dia"` not `"Día"`). Match this when writing new translations by hand — do not assume all-ASCII or all-native.
- `lib/l10n/parts/*.json` (e.g. `part_therapy_capture.json`) are NOT consumed by any build script (confirmed via grep — `l10n.yaml`'s `arb-dir` points only at `lib/l10n`, gen-l10n reads the `app_*.arb` files directly). They're checked-in bookkeeping mirrors of specific batches' strings; keep them in sync only when a task explicitly names one (as the mail-fix item did), not proactively for every new key.
- `test/l10n_completeness_test.dart` is a hard gate: fails on any KEY missing from a locale or any EXTRA key not in English (source of truth = `app_en.arb`). Untranslated-fallback-text is only a soft/printed warning, not a failure. Always add a new key to ALL 7 locale files in the same batch, never just English.
