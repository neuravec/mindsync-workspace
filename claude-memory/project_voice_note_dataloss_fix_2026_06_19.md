Critical data-loss fix shipped to disk 2026-06-19 (therapist tester quit after losing a 3-min dictated note 3×).

**Root cause** — `lib/screens/debrief_capture/cubit/debrief_capture_cubit.dart` (shared by debrief / prep-card / between-session NOTES) treated the live WebRTC transcript as source-of-truth and the recorded M4A as a mere fallback. On Stop it snapshotted the partial live transcript, tore down the transcription session before the final `input_audio_transcription.completed` arrived, and if the (stale) transcript was <10 words it **deleted the complete M4A** (`_cleanupRecordingFiles`) and showed a "too short" screen → full audio gone.

**Fix (frontend-only, NO backend change — backend already transcribes the M4A server-side via gpt-4o-mini-transcribe with no min-duration/word gate):**
- `stopAndSubmitRecording()` now ALWAYS uploads the full M4A; too-short decided **solely from file size** via pure `@visibleForTesting static decideStopOutcome({path, fileSizeBytes})` → `StopDecision{noAudio,tooShort,upload}`, `kMinUsefulBytes=2048` (corruption guard only). M4A is **never deleted before a confirmed save** (only `_uploadRecording` deletes on success). Re-entrancy guard `_isStopping` (blocks the 15-min auto-stop Timer racing a user tap). `tooShort` retains the file + now offers "Use Text Instead".
- `close()` made async: on back-navigation/route-change while recording it `await _recorder.stop()` (writes the moov atom) then copies to `$path.autosave` so the EXISTING in-screen recovery banner (`_checkForAutoSave`/`recoverAutoSave`) can restore a finalized file. No new prefs keys, no splash routing.
- Removed dead `DebriefCaptureShortTranscript` state/widget + `continueRecordingFromShort/addMoreTextFromShort/saveAsQuickNote` (live transcript no longer gates submission). Freezed regenerated.
- **Settle-grace (PO-requested "wait 1-2s" safeguard):** on the upload path, emit `processing(captured)` instantly, then `_settleTranscription()` waits ≤`_kStopSettleMs`=1200ms for the final live-transcript chunk before teardown — defense-in-depth; the M4A upload is the real guarantee. semantic_vad → NEVER sends a manual `input_audio_buffer.commit`; bounded `.timeout`, guarded `Completer`, short-circuits if no live session.

**Reflect / generic voice** (`lib/screens/audio_chat/cubit/audio_chat_cubit.dart`) had the same race with NO audio backup — only mitigation is wait-before-teardown. `endCall()` now `async Future<List<ChatMessageModel>>`: `_drainFinalUtterance()` waits ≤`_kEndCallDrainMs`=2500ms for the final user `transcription.completed` AND its persistence POST before `close()`; gated on `_pendingUserTranscript` (set on `input_audio_buffer.speech_started`, cleared + drain-completed AFTER the POST so teardown can't race mid-POST). Messages snapshotted AFTER the drain; `close()` defensively completes any pending drain. Callers awaited: `audio_chat_body.dart:39` (PopScope) + `:147` (end InkWell) made async; `reflect_voice_body.dart:140`. Discard-confirm dialog unchanged (runs before endCall = user intent).
