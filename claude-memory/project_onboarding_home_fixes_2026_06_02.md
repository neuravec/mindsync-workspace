**5. Name-empty regression (Home + Account, multiple accounts) — ROOT CAUSE + FIX.** Registration defers profile creation (GDPR): SignUpCubit saves `pending_profile_json` to SharedPreferences; `TherapyOnboardingCubit.acceptConsent()→_flushPendingProfile()` did a single silent `POST /profile`. Backend `crud.create_user_profile` is a PLAIN INSERT (no upsert) — if a profile row exists or acceptConsent threw, POST failed, catch swallowed it, name never persisted/retried. Fix (frontend-only, no backend/migration): `UsersManager.flushPendingProfile({currentUid})` = UPSERT (POST→PUT fallback) + STRICT uid ownership (pending payload now stamped with uid by SignUpCubit; legacy uid-less pending is DISCARDED not applied — GDPR: no cross-user PII bleed on shared devices) + clears only on success. `MainPageCubit._repairMissingName()` self-heals on getUserProfile()/carouselCheck() (capped one attempt/session via `_nameRepairAttempted`, only when `pendingProfileHasName()`). Also fixed a `FirebaseAuth.instance` un-try/caught access that could block consent.

**CAVEAT — existing broken accounts do NOT auto-recover:** their legacy pending has no uid → discarded for safety. They recover by RE-REGISTERING (cleanest for testing) or re-entering the name in Account → Save. All NEW registrations (this build) stamp uid → flush+self-heal work fully.

Orchestrated via Workflow (investigate → 4 parallel flutter-mobile impl → qa+adversarial verify → harden+reverify). Adversarial review caught the GDPR uid-bleed (HIGH) + network-wedge (MED) which were then hardened.
